Project: Wasel

Twenty questions against a fictional Egyptian ride-hailing app — every Day 01-05 technique SQLite supports, on a completely different business than Rawaj.

What you'll be able to do after this lesson

  • Apply every Day 01-05 technique SQLite supports to a fresh schema (cities, drivers, riders, vehicles, trips, ratings) from a completely different business than Rawaj.
  • Spot a driver-supply gap with an anti-join, then confirm with a second query whether it's a real demand problem or a data problem.
  • Save a "top drivers by earnings" view and reuse it across later questions instead of repeating the JOIN chain.
  • Materialize a temp table once, then pull two different breakdowns from it without re-running the same filter twice.
  • Rank drivers within their own city with RANK(), and see exactly how it handles a real 3-way tie.
Exercises Solutions Notebook Source

Randa runs operations analytics at Wasel, the ride-hailing app expanding across Egypt. Leadership has a fixed budget for driver incentives next quarter, and wants her recommendation on which cities actually need it.

Marketing also wants to know whether the promo codes they keep pushing are paying for themselves, and someone flagged a coverage gap in the last leadership meeting that needs a real answer, not a guess. There's no new SQL syntax in this project: it's Days 01-05 (filtering, aggregation, JOINs, CASE, anti-joins, subqueries, CTEs, views, temp tables, window functions — everything except stored procedures, which SQLite has no equivalent for) applied to a completely different business from Rawaj. Nothing about the e-commerce schema carries over except the SQL.

•The dataset

Wasel (واصل — "arrived") is a fictional Egyptian ride-hailing app. Riders and drivers meet at trips, the transactional core (6,000 rows, with separate pickup and dropoff cities since cross-city rides are common in Greater Cairo) — everything else exists to describe one side of that trip or the other:

driver_city_coverage is the one genuine many-to-many in this schema — every driver covers their own home city, and about a third of drivers based in Cairo, Giza, or Qalyubia (practically one metro area) also cover a neighboring one. ratings are deliberately incomplete: some completed trips have a rider-side rating, some have a driver-side rating, some have both, and some have neither (Q19 asks exactly how many). See the full schema reference for every table and column if you need to check a name while working through the questions below.

Before you start

Databases/wasel.sqlite is already included in this repo — no download and no setup script needed. No MySQL server or .env either — project_07.ipynb connects with a relative path (sqlite:///../Databases/wasel.sqlite), same as every project day.

•Reused patterns, worth knowing before you start

Two questions in the middle of the list lean on techniques you've already seen, applied slightly differently:

project_07.ipynb
DROP VIEW IF EXISTS top20_drivers; CREATE VIEW top20_drivers AS SELECT d.driver_id, d.driver_name, SUM(t.fare_amount) AS total_earnings FROM trips t JOIN drivers d ON t.driver_id = d.driver_id WHERE t.status = 'completed' GROUP BY d.driver_id, d.driver_name ORDER BY total_earnings DESC LIMIT 20;
A view, not a repeated query

Q17 (each top-earner's best day) filters against top20_drivers directly instead of recomputing "who's a top earner" from scratch — exactly the Day 04 payoff of naming a query once.

RANK() on a real tie

Q14 ranks drivers by trip count within their own city — Alexandria has a genuine 3-way tie at 39 trips each, and RANK() gives all three rank 4 and skips straight to rank 7 for the next driver, exactly the tie-handling behavior Day 05 covers.

If something doesn't run

Restart the kernel and run every cell from the top if a later question errors out — Q11's saved view and Q13's temp table are both reused by questions that come after them. A sqlite3.OperationalError: unable to open database file almost always means Jupyter was launched from the wrong folder: start it from inside Day 07/, since the connection string is a relative path. See this day's README.md for more.

Randa's answer

Giza is the clear case for incentive budget — it leads on cross-city trip share (Q9), has the longest average completed-trip distance of any city (Q12), and its drivers earn the highest average fare per trip in the network. All three signals point the same way. Alexandria looked like a second candidate on Q12 alone, but doesn't hold up once checked against Q9: it sits at a flat 0% cross-city, and every city in the dataset falls within a narrow band on distance — not a gap worth acting on by itself. One strong signal, not two, is the honest version for leadership. The promo codes barely anyone redeems (Q4) get retired. And the "coverage gap" flagged in the meeting (Q20) turns out to be a one-driver staffing problem in Suez, not a demand problem — a very different fix than the one leadership was about to approve.
