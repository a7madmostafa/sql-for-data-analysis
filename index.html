Self-paced course

SQL for Data Analysis

A 7-day self-paced course for complete beginners: five days of core SQL syntax, one day of Python connectivity, and one applied project on an unfamiliar dataset. Pick a day below to start reading.

Who this is for

  • Aspiring data analysts
  • Data science beginners
  • Students
  • Professionals transitioning into data

No prior SQL required.

What you'll be able to do

  • Query relational databases with SQL fundamentals
  • Combine data across tables with JOINs
  • Aggregate and transform data with GROUP BY, CASE, and string/date functions
  • Write subqueries, CTEs, and window functions for analytical SQL
  • Connect SQL to Python with SQLAlchemy and pandas
  • Apply everything to an unfamiliar dataset, independently

Learn → Practice → Challenge → Apply — the rhythm of every day below.

SQLData AnalysisDatabasesPythonpandasAnalytical Thinking

Before you start

No prior SQL is assumed, and no programming knowledge is needed until Day 06. Each day follows the same rhythm: read the concepts, work through the walkthrough alongside a real database, then practice on your own with the exercises and check your answers against the solutions. Days vary in length — some are quick, others (Day 03's JOINs, Day 06's Python setup) take longer — so pace yourself by what you've actually absorbed, not the clock. There's no schedule to keep, just the order above.

  • Days 01–05 need a MySQL server and Databases/rawaj_db.sql (see "Before you start" inside each day's card below).
  • Days 06–07 need Python instead — pip install -r requirements.txt, and a .env file for Day 06's MySQL half only. Day 07 needs neither MySQL nor .env.

Every walkthrough .sql file and notebook has a "Worked Examples" HTML twin — every statement plus its real output, already run, so you can read the material and its actual results without a database or Jupyter running yet.

Lesson days

DAY 01
SQL Foundations

SELECT, LIMIT/OFFSET, DISTINCT, ORDER BY, COUNT — entities, attributes, and the three relationship types.

▸What you'll learn
  • Explain what SQL, a database, and a DBMS are — and how they relate to each other.
  • Tell relational and non-relational databases apart, and know why this course uses MySQL.
  • Read an entity-relationship diagram: entities, attributes, and the three relationship types.
  • Write your first real queries: SELECT, LIMIT/OFFSET, DISTINCT, COUNT, ORDER BY.
  • Recognize the mistakes almost every beginner makes in their first week, before you make them.

Before you start: run Databases/rawaj_db.sql once — creates and loads the rawaj database.

DAY 02
Filtering & Aggregation

WHERE, comparison operators, AND/OR, BETWEEN, IN, NULL checks, LIKE, GROUP BY, aggregates, DATE functions.

▸What you'll learn
  • Filter rows with WHERE, comparison operators, AND/OR, BETWEEN, IN, and NULL checks.
  • Match text patterns with LIKE.
  • Aggregate per group with GROUP BY, and know when WHERE can't do the job but HAVING can.
  • Pull pieces out of a date/time column and reason about date ranges with DATE functions.

Before you start: run Databases/rawaj_db.sql once — creates and loads the rawaj database. Shared by Days 01–05.

DAY 03
JOINs, CASE & String Functions

INNER/multi-table JOINs, JOIN + GROUP BY/HAVING, LEFT/RIGHT JOIN, anti-joins, FULL JOIN via UNION, CASE, string functions.

▸What you'll learn
  • Combine rows from multiple tables with JOIN, and know when a plain (INNER) JOIN silently drops rows you wanted.
  • Keep unmatched rows with LEFT/RIGHT JOIN, and use that same pattern to write an anti-join.
  • Emulate MySQL's missing FULL JOIN with UNION.
  • Aggregate and filter across joined tables with GROUP BY and HAVING.
  • Add conditional logic with CASE — labeling rows, and bucketing continuous values into tiers.
  • Trim, slice, and rebuild text with LTRIM/RTRIM/TRIM, LEFT/RIGHT/SUBSTRING/LOCATE, CONCAT, REPLACE, LOWER/UPPER/LENGTH.
  • Fill in gaps left by a CASE expression with COALESCE/IFNULL.

Before you start: run Databases/rawaj_db.sql if you haven't already.

Reading Worked Examples Walkthrough & Exercises
DAY 04
Subqueries, CTEs & Views

Scalar and row subqueries, derived tables, CTEs, chained CTEs, temp tables, views.

▸What you'll learn
  • Write a scalar subquery (one value) and a row subquery (a tuple, matched with IN).
  • Use a subquery as a derived table in FROM, then rewrite the same idea more readably with a CTE.
  • Chain multiple CTEs together, and know when to reach for a temporary table or a view instead.
  • Choose the right tool — subquery, CTE, temp table, or view — for a given reuse scenario.

Before you start: run Databases/rawaj_db.sql if you haven't already.

Reading Worked Examples Walkthrough & Exercises
DAY 05
Window Functions & Stored Procedures

Running totals, RANK/DENSE_RANK/ROW_NUMBER, LAG/LEAD, stored procedures with IN/OUT parameters.

▸What you'll learn
  • Compute a running total, rank, or row-to-row comparison with a window function, without collapsing rows the way GROUP BY does.
  • Reset a window per group with PARTITION BY, and tell RANK/DENSE_RANK/ROW_NUMBER apart by how each handles ties.
  • Look at a neighboring row with LAG/LEAD, for month-over-month style comparisons.
  • Write, and CALL, a stored procedure with IN and OUT parameters, using DELIMITER correctly.

Before you start: run Databases/rawaj_db.sql if you haven't already.

Reading Worked Examples Walkthrough & Exercises
DAY 06
Python Connectivity: MySQL & SQLite

No new SQL — everything from Days 01–05, now reached from Python. First day needing a Python environment, and the first notebooks instead of plain .sql files.

▸What you'll learn
  • Use the raw cursor pattern (connect, cursor, execute, fetchall) that every higher-level tool is built on.
  • Connect from Python to MySQL with SQLAlchemy, credentials pulled from a local .env file — never hardcoded.
  • Run SQL directly inside a notebook with jupysql's %sql/%%sql magic, and load results into pandas.
  • Pass values into a query safely with bound parameters, instead of an f-string that opens the door to SQL injection.
  • Avoid two real driver gotchas that only show up once you call stored procedures from Python.
  • Migrate a live MySQL database into a local SQLite file with pandas, verify the migration, and connect to the copy two ways.
  • Turn a query result into a chart with pandas — the payoff SQL alone can't give you.
  • Recognize the handful of SQL differences between MySQL and SQLite that Day 07 will lean on.

Before you start: run Databases/rawaj_db.sql and Day 05's walkthrough if you haven't already (this notebook CALLs the procedures it creates). Copy .env.example to .env and pip install -r requirements.txt.

DAY 07
Project: Wasel

20 questions on a fictional Egyptian ride-hailing app — filtering, JOINs, CASE, anti-joins, subqueries, CTEs, views, temp tables, and every window function. No new SQL, no MySQL/.env needed.

▸What you'll learn
  • Apply every Day 01–05 technique SQLite supports to a fresh schema (cities, drivers, riders, vehicles, trips, ratings) from a completely different business than Rawaj.
  • Spot a driver-supply gap with an anti-join, then confirm with a second query whether it's a real demand problem or a data problem.
  • Save a "top drivers by earnings" view and reuse it across later questions instead of repeating the JOIN chain.
  • Materialize a temp table once, then pull two different breakdowns from it without re-running the same filter twice.
  • Rank drivers within their own city with RANK(), and see exactly how it handles a real 3-way tie.

Before you start: Databases/wasel.sqlite is already included in this repo — nothing to download or set up. No MySQL server or .env needed — this day runs entirely on SQLite.
